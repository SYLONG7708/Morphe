# SyMorphe 自動更新、復原與 32／64 位元

## 裝置使用

安裝符合原套件的授權版或無授權版，開啟「自動生態系更新」。
兩個 Manager APK 都包含 ARM32、ARM64、x86、x86_64，Android 會自行載入適用版本。
首頁與安全更新中心都以同一份 RSA 驗證的更新清單，按套件名稱及 versionCode 決定更新。

YouTube 自動修補會讀取 Android 實際支援的架構清單：

| Android 系統 | 自動選擇 |
|---|---|
| 32 位元 ARM | armeabi-v7a |
| 支援 ARM64 的 64 位元系統 | 優先 arm64-v8a；只有系統支援時才接受 ARM32 來源 |
| 只有 ARM64 的系統 | 排除 ARM32 |
| x86／x86_64 | 按系統支援順序選擇官方補丁宣告的版本 |

CPU 硬體具備 64 位元能力，不代表安裝的 Android 就支援 64 位元。
下載後還會檢查 Google 簽章、套件、版本、SDK、雜湊及 APK 內的原生函式庫。
YouTube 修補產出會保留系統支援的一種架構；無原生函式庫的 APK 保持通用。
無相容來源時停止，不將錯誤架構當作成功。

既有本機預載補丁可從簽章更新清單直接更新，保持原來源 UID 與設定。
新補丁需通過版本、SHA-256、修補引擎及 metadata 載入檢查才替換原檔。
已更新的較新可用補丁不會在下次啟動被內建基線降回。
網路失敗會按退避排程重試；讀到不同批次的 latest 清單／簽章時，改從固定發行 tag 取得並重新驗證。
一般 Android 的安裝確認仍由系統顯示；已授權 Shizuku／root 的裝置沿用相應安裝方式。

## 雲端自動維護

- `Sync official stable Manager` 每 6 小時檢查官方穩定 tag；可無衝突合併的更新在兩個版本的測試、Lint、APK 建置通過後推送，並觸發正式簽章發版。
- 缺少的 Morphe Maven 依賴由官方精確 tag 原始碼重建，測試通過才使用，記錄 commit 與 SHA-256。
- `Signed ecosystem release` 每 6 小時檢查最新官方補丁及 MicroG；沒有變更時只驗證／修復 discovery 連結，不重建 APK。
- SDK 明確指定 `platform-tools`，不再要求已撤下的舊 `tools` 套件。已辨識的暫時網路錯誤最多 3 次重試。
- 發版失敗會使用新 runner 重試，單一 run 最多 3 次 attempt；仍失敗則觸發官方來源同步檢查並保留目前 Release。
- 所有正式檔案使用固定 tag 網址，先上傳草稿並完成證明後才公開。已公開版本不覆寫；發版後的指標失敗可由簽章 manifest 重建。
- 無上游更新的月份會留下一筆最小維護 heartbeat，降低公開儲存庫因長期無活動而停用排程的風險。

GitHub 的排程可能延後。合併衝突、官方 API 不相容、憑證失效、權限撤銷或服務長期停用，無法保證自動修好；工作摘要及診斷 artifact 會保留實際錯誤，驗證失敗不會冒充成功發版。
