# SyMorphe 架構與安全性

## 更新資料流

```text
MorpheApp 上游 Releases
  ├─ 未修改 patches.mpp ─┐
  └─ 未修改 MicroG APK ──┼─ GitHub Actions 驗證／重新命名
SyMorphe 原始碼 ─────┘
              ↓
      獨立 Android 金鑰簽署 Manager APK
              ↓
     產生 SHA-256 + 套件／版本／SDK／ABI／簽署者資料
              ↓
      獨立 RSA 金鑰簽署每個檔案與 update-manifest.json
              ↓
        SYLONG7708/Morphe GitHub Release
              ↓
  App 內釘選憑證驗證 → 裝置選版 → 背景下載 → 安裝／本機修補
```

## 信任模型

`update_signing_cert.der` 是 App 內唯一信任根。GitHub 只負責傳輸；即使帳號或 CDN
被竄改，攻擊者沒有離線私鑰就無法產生通過驗證的清單。清單序號只可增加，
`lastAcceptedManifestSequence` 會拒絕重播舊版本。

每個 APK 除了檔案簽章與 SHA-256，還會解析並比較：

- package name、versionName、versionCode；
- minSdk 與裝置 Android SDK；
- ABI 與 `Build.SUPPORTED_ABIS`；
- APK 憑證 SHA-256；
- 若套件已安裝，必須與既有簽署鏈相交。

## YouTube 更新

SyMorphe 不取得 Google APK。它先更新 `.mpp`，再用修補套件的相容性資料檢查：

1. 已安裝的 `com.google.android.youtube`；
2. 使用者先前保存的原始 APK。

一般模式只在版本精確相符時自動採用；split APK 會先在本機封裝、篩選裝置 split
並合併，再修補與簽署。沒有安全相容來源時會顯示等待狀態，不會強行套用。

## 安裝權限

- Shizuku 已執行且已授權：可靜默安裝。
- Root 已授權：可用 package manager 靜默安裝。
- 其他情況：啟動 Android 系統安裝器，由使用者確認。

Android 不允許普通第三方 App 無提示安裝，設計不會繞過此平台保護。

## 金鑰分離

- Android keystore：簽署 `com.sylong.symorphe` APK，並由 App 內建憑證指紋檢查防止竄改後重新簽署。
- Update PKCS#12：只簽署下載檔與清單，不參與 Android 套件簽署。
- 公開 DER 憑證：可提交；兩把私鑰只存在本機忽略目錄與 GitHub Actions Secrets。
