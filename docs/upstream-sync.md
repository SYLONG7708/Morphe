# 官方 Manager 來源同步

`SYLONG7708/Morphe` 是保留客製授權、更新及簽章流程的正式儲存庫；官方來源為 `MorpheApp/morphe-manager`。另建儲存庫不能消除兩邊修改同一檔案時的合併衝突，因此維持同一個正式來源與可追溯的上游標籤。

## 自動流程

- 每日 01:37 UTC 檢查官方最新正式 Release。版本未變時不建置，也不發布。
- 可以合併時，先驗證 Python 工具、Android 單元測試、Lint，以及授權版與免裝置授權版的 Release 建置。全部通過才推送合併並啟動簽章發布。
- 原始碼衝突時，中止合併，保留現行已簽章 Release，保存 `upstream-sync.json` 診斷 artifact，並按官方標籤建立一次 GitHub Issue。此情況代表需要人工整合，排程不再每天重複發送失敗通知。
- 網路、權限、依賴、測試或建置錯誤仍會使工作流程失敗；復原流程只對暫時性錯誤有限度重試。

## 新版遇到衝突時

1. 從 `main` 建立隔離工作樹，抓取 Issue 指向的官方標籤與提交。保留原始工作目錄的未提交修改。
2. 解決衝突時保留客製授權、簽章、更新渠道與受審核的來源；不得直接採用官方發布工作流程覆蓋本儲存庫的工作流程。
3. 執行 `python3 -m unittest discover -s tools -p 'test_*.py'`，再依 `upstream-sync.yml` 跑兩種 Release 的單元測試、Lint 與建置。
4. 使用保留官方提交為第二父提交的 Git merge commit；合併 PR 時選 **Create a merge commit**，不要 squash。否則下次同步會再次遇到同一批歷史衝突。
5. 驗證 `config/upstream-manager.json` 的標籤與提交、正式簽章發布結果，再關閉對應 Issue。

任意未來的程式碼衝突無法安全地無條件自動解決；同步流程會明確記錄需要檢查的版本與檔案，並持續提供目前已驗證的版本。

## 已審核的整合規則

`config/upstream-resolutions.json` 與其補丁一律從合併前的 `HEAD` 讀取。每條規則核對共同祖先、本地、上游檔案的 SHA-256，以及補丁與結果的 SHA-256；任何不同的來源都不能套用舊規則。

- `inputs.upstream: null` 精確代表上游刪除了檔案，不代表任意內容，也不等於空檔案。刪除結果同樣必須明列為 `result_sha256: null`。
- 補丁預設從本地內容套用；`patch_base: upstream` 可從已核對的上游內容套用，避免重複收錄整個上游改版。空補丁表示保留所選內容，仍須通過全部輸入與結果雜湊檢查。
- 帶有 `inputs.merged` 的規則額外核對 Git 自動合併後的檔案，僅在四個輸入完全一致時修正文字合併未能辨識的 API 或資源整合問題。
- 上游新檔案也可使用 `inputs.merged` 規則；`inputs.base` 與 `inputs.local` 必須精確符合檔案不存在的 `null`，上游及自動合併內容仍須核對雜湊。
- `requires` 指定必須一起成功的配套規則。缺少任何配套時中止整次合併，保留現行版本。

v1.35.0（`df78a1ebedb6047f50f8bb6b04c25ad524e3dec6`）的規則保留裝置授權、簽章更新、YouTube 來源與架構驗證、分類設定，以及 WorkManager 更新通知；將舊圖示遷移至上游產生器時繼續使用 SyMorphe 圖案及既有啟動別名。新版 `NativeLibs`、偏好設定工廠與安裝狀態 API 的本地呼叫端也與這組規則一起套用，防回滾序號仍使用同一個儲存鍵及驗證邏輯。`settings.gradle.kts` 保留已驗證的依賴來源，不自動替換成相鄰目錄中的來源。

v2.0.0（`445b31adfb50ec95307223336ab3b908b7d026bc`）將修補流程抽離為 `PatchFlow`、重組設定頁並新增 `patcher-core`。這組規則一起遷移一鍵 YouTube、簽章更新中心與分類設定，保留授權、套件身分、來源驗章、雜湊與架構檢查，以及 WorkManager 更新通知；檔案驗證呼叫端配合新版可取消的雜湊 API。只有存在 `patcher-core` 時才安裝額外的 JDK 25 並執行核心測試；既有衍生元件仍使用 JDK 21，兩種版本原有的測試、Lint 與建置關卡繼續執行。同時修正分段下載在伺服器回傳超額資料時未結束回應工作的停滯，原有下載測試保留全部內容斷言並增加逾時上限。

v2.1.0（`fb8d86aee8c5ae90038f4a062bc36975b1bd217c`）的寮語規則保留全部上游翻譯與本地 SyMorphe 註解，僅套用於三方來源、補丁及結果雜湊完全吻合的衝突。此版本的內嵌 JVM 改用 JDK 17，共用建置 action 同時提供 JDK 17 與 25，以支援同步前後的來源；預設 JDK 21 保持不變。

v2.2.0（`2c2bdc6a8368fa790ca2e3a57b050070a2c36eea`）的八條規則一起整合 JVM 相容性修正、來源排序、更多應用卡片及相依版本，保留裝置授權、停用備份、補丁分類與 YouTube ABI 資訊。文字合併成功的一鍵流程也必須將所選版本改為含來源的 `BundledAppTarget`；架構測試配合新的來源順序參數，保留原有 ABI 斷言並新增排序及停用來源檢查。所有規則透過 `requires` 綁定，任何來源或配套不符都中止整次整合，不會將受阻版本標記為已更新。

`.github` 全樹由本發布渠道維護。上游修改了本地已刪除的工作流程或 action 時，先解決該刪除衝突，再從合併前的 `HEAD` 還原整樹，避免 `git restore` 失敗或復活上游發布流程；既有排程保持不變。

加入規則本身不會更新 `upstream-manager.json`。只有實際合併完成後才準備新來源紀錄，且仍須通過兩種版本的單元測試、Lint 與 Release 建置，才能由原有同步流程發布。
